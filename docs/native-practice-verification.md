# 실제 내비 연습 경로 검증

검증일: 2026-11-15. Pleos 에뮬레이터의 실제 NaviHelper 서비스와 별도 검증 패키지를 사용했다. 실차 주행이나 도로 적합성 검증은 아니다.

## 구현

- 홈에서 실제 목적지 조회와 목표 기반 연습 경로 준비를 우선 표시하며 예시 지도 체험은 별도 진입으로 분리한다.
- 현재·최근 내비 목적지와 이전 SDK 기록의 목적지를 후보로 사용한다. 도로별 훈련 적합성은 평가하지 않는다.
- 사용자가 승인하면 기본 내비 경로를 편안한 경로 또는 추천 경로 옵션으로 변경한다. 경로 계산 완료와 목적지·옵션·시간 제한을 확인한 후 기록을 허용한다.
- 왕복 경로 요청은 현재 출발지를 목적지, 선택한 장소를 경유지로 전달한다. SDK 장소 ID가 있는 실제 목적지를 경유한 왕복 계산·기록·종료와 메타데이터 저장까지 추가 검증했다. 좌표만 있는 경유지의 반환 정보 제한은 아래에 기록한다.
- 차선 변경 최소화는 실제 경로에서 검증할 수 없어 사용자가 해당 조건을 해제해야 계산할 수 있다.
- 실제 연습 세션은 선택 목표, 연습 목적지, 왕복 여부, 최대 시간, 출발 전 예상 시간·거리를 저장하고 리포트와 다음 연습에 전달한다.
- Room v2에서 v3으로 변경하며 새 메타데이터를 추가한다.

## 실행 확인

1. 실제 내비 목적지 더현대서울의 추천 경로를 요청했다. SDK가 기존 경로를 취소한 뒤 새 경로 계산 완료를 알리는 순서를 확인했다.
2. 최대 45분 설정에서 SDK 예상 52분을 받아 기록 시작을 차단했다. 제한을 임의로 완화하지 않고 사용자 선택을 60분으로 변경했다.
3. 최대 60분으로 재요청하여 SDK 예상 55분·23km의 경로를 확인했다. 저장 동의 후 회전·교차로 목표로 시작했다.
4. 약 16초 동안 위치 업데이트 15건을 저장하고 수동 종료했다. 리포트와 DB에서 SDK / Practice / Turns / NATIVE, 예정 3300초·23000m, 최대 60분과 목적지가 일치했다. 정지 상태의 위치 샘플이므로 실제 기록 거리는 0m였다.
5. v2에 있던 기존 기록 5개의 모든 기존 필드가 v3에서 보존됨을 비교했다.

## 단위 검증 및 한계

좌표·POI 동일성, 시간 제한의 초 단위 경계, 유효한 왕복 출발지·경유지, 경로 옵션·목적지·경유지 일치, 오래된 응답·바뀐 예상 값 거부, 후보 중복 제거와 다음 연습의 목표 보존을 검증한다.

편안한 경로 옵션은 에뮬레이터 내비가 그대로 적용하지 않을 수 있다. 이 경우 실패를 표시하고 다른 옵션으로 다시 계산하도록 한다. 추천 옵션의 편도와 SDK 장소 ID가 있는 왕복을 전체 실행 확인했다. 현재 SDK에는 요청 ID가 없으므로 완료 콜백과 최신 경로 상태를 함께 확인하며 응답 대기 중 중복 계산을 차단한다.

연습 가능한 도로 목록 검토, 실차·교통 상황 검증, 상황별 자동 음성, 차량·ADAS 분석, 앱이 종료된 상태의 참여 알림은 완료 범위가 아니다. 백그라운드 기록은 별도 검증 문서를 참고한다.

## 추가 왕복 확인

실제 SDK 장소 ID가 있는 목적지를 경유해 출발지로 돌아오는 추천 경로의 목적지·경유지 동일성과 최대 시간을 확인했다. SDK 연습 세션의 시작·종료 후 목표·왕복·경유지·예상 시간/거리가 보존됐다. 이동 완주나 도착을 GPS로 모의한 검사가 아니라 계산→기록→종료 흐름 검사다.

좌표만 전달한 경유지는 이 에뮬레이터가 좌표 `0,0`, 표시 좌표 null, 빈 POI ID로 반환했다. 앱이 요청값으로 대신 채우지 않고 확인 실패를 표시하며 편도/다른 장소로 다시 계산하도록 처리했다. SDK POI ID가 일치하는 경유지는 확인할 수 있다. 자세한 실행 범위는 [MVP 검증](mvp-batch-verification.md)에 기록했다.
