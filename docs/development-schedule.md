# Thrive 개발 일정 초안 — 12월 3일 MVP 완성

작성일: 2026년 11월 15일

## 12월 3일까지 완성할 모습

**2026년 12월 3일까지, 연습 준비부터 주행 기록·복습·다음 연습까지 한 흐름으로 시연할 수 있는 Thrive MVP를 완성한다.** 사용자가 목표와 시간을 정하고 실제 내비 경로를 확인한 뒤 기록을 시작하면, 주행 중 수집한 정보를 저장하고 종료 후 리포트에서 다시 볼 수 있어야 한다. 리포트에서 선택한 다음 연습은 이전 목표와 사용자 응답을 반영해 준비 화면으로 이어져야 한다.

최종 결과물은 설치 가능한 APK, 주요 사용 흐름을 보여 주는 시연 영상, 설치·실행 방법과 구현 범위를 설명하는 문서다. 12월 3일은 이번 초안에서 정한 내부 개발 완료 목표일이며, 공모전의 공식 제출 일정과는 별개다.

## 현재까지 진행된 내용

11월 15일 기준으로 프로필과 설정 저장, 실제 내비 목적지 조회, 주행 시간·위치 기록, 종료 후 리포트 조회와 다음 연습 연결이 구현돼 있다. 실제 편도 연습 경로 계산, 화면을 닫은 뒤의 백그라운드 기록, 알림을 통한 기록 종료와 중단 복구도 에뮬레이터에서 검증한 기록이 있다. 기본 내비 연결이 유지되는 동안 주차 상태를 확인해 연습 참여를 제안하는 기능도 구현돼 있다.

남은 기간에는 이 기반 위에 주행 중 발생한 내비 사건을 저장하고, 그 내용을 복습과 안내에 연결한다. 왕복 경로와 예외 상황을 확인하고, 주요 화면의 디자인과 사용 흐름을 정리한 뒤 시연 결과물까지 마무리한다. 이미 동작하는 기능은 유지하면서 아직 확인되지 않은 부분을 날짜별로 닫아 나간다.

현재 상태의 근거는 [개발 현황](../../pleos/DEVELOPMENT_STATUS.md)과 이 저장소의 기능별 검증 문서다. 아래 일정은 남은 작업을 배치한 제안이며, 각 단계의 완료 여부는 실제 구현·검증 결과로 갱신한다.

## 11월 16일~18일: 주행에서 발생한 일을 기록으로 남긴다

먼저 내비게이션의 재탐색, 경로 취소, 도착 사건을 주행 기록에 연결한다. 각 사건이 어느 주행에서 언제 발생했는지와 어떤 SDK 응답을 근거로 저장했는지 확인할 수 있도록 한다. 같은 응답이 반복돼도 사건이 중복으로 쌓이지 않고, 종료된 주행에 뒤늦은 응답이 잘못 들어가지 않도록 처리한다.

리포트에서는 저장된 사건을 시간 순서에 따라 확인할 수 있게 한다. 사건을 수집하지 못한 경우에는 그 상태를 표시한다. 재탐색이 있었다는 사실을 사용자의 실수나 운전 실력 저하로 해석하지 않는다.

**11월 18일까지는 주행을 종료하고 앱을 다시 실행해도 해당 주행의 요약과 내비 사건을 함께 조회할 수 있는 상태를 만든다.** 기존 기록의 보존과 세션별 사건 분리도 이때 확인한다.

## 11월 19일~22일: 기록을 복습과 다음 연습으로 연결한다

저장한 내비 사건과 사용자가 남긴 부담 응답을 리포트에 연결한다. 사용자가 실제로 확인할 수 있는 관측 내용과 자신의 응답을 구분해 보여 주고, 다음에 무엇을 다시 연습할지 이유와 함께 제안한다. 제안을 선택하면 목표와 시간 등 필요한 조건이 다음 연습 준비에 이어져야 한다.

상황별 안내는 SDK가 실제로 제공하는 경로·회전 안내 정보의 범위를 먼저 확인한다. 활용 가능한 정보로 안내 후보를 만들고, 같은 상황의 반복 안내, 오래된 후보, 음소거·기록 종료 이후의 출력을 막는다. 실제 주행 중 자동 음성 출력은 내비 음성·통화·차량 경고와의 충돌을 확인한 경우에만 활성화한다. 11월 22일까지 검증이 끝나지 않으면 이번 버전은 준비 단계의 수동 안내를 유지하고, 후보 생성·취소 동작은 별도로 검증한다.

왕복 연습도 이 기간에 전체 흐름을 확인한다. 출발지에서 경유지를 거쳐 돌아오는 경로가 의도대로 계산되는지, 예상 시간이 사용자의 제한을 넘을 때 시작을 막는지, 목적지나 경유지가 바뀌었을 때 다시 확인하도록 하는지 검증한다. 지원하지 않는 경로 옵션은 실패 이유와 가능한 대안을 보여 준다.

**11월 22일까지는 연습 준비 → 경로 확인 → 기록 → 리포트 → 다음 연습을 한 번에 시연할 수 있게 한다.** 왕복 경로와 자동 음성은 검증 결과에 따라 제공 범위를 확정하고, 제한이 있는 경우 사용자가 화면에서 이해할 수 있도록 반영한다.

## 11월 23일~26일: 주요 화면과 예외 상황을 마무리한다

메인, 연습 설정, 경로 준비, 주행 기록, 리포트, 기록 목록의 화면을 실제 사용 순서대로 정리한다. 메인에는 현재 적용한 밝은 배경을 기준으로 글자·버튼·패널의 대비를 맞추고, 다른 화면은 기존 스타일과의 연결을 확인한다. 화면마다 용어와 주요 버튼의 역할을 일관되게 맞춘다.

목적지가 없거나 기록이 비어 있는 상황, 권한 거부, 내비 연결 실패, 경로 계산 실패에서 다음 행동을 알 수 있도록 문구와 재시도 동작을 보완한다. 넓은 창과 분할 창, 큰 글자 배율에서도 핵심 정보와 버튼이 잘리지 않는지 실제 렌더로 확인한다.

기록 안정성도 함께 점검한다. 최소 60분의 연속 기록을 한 차례 확인하고, 다른 앱 전환·화면 재생성·위치 수신 단절·서비스 중단·앱 재실행 상황에서 저장과 복구가 일관되게 동작하는지 검사한다. 저장 실패를 성공으로 표시하거나 중단 전후의 데이터를 잘못 합치는 문제를 우선 수정한다.

**11월 26일까지는 핵심 흐름을 막는 오류를 해결하고, 검증한 환경과 남은 제한을 문서로 남긴다.** 이후에는 새 기능 추가를 멈추고 오류 수정과 시연 준비에 집중한다.

## 11월 27일~30일: 시연과 설명 자료를 완성한다

대표 시연은 연습 목표 선택에서 시작해 실제 내비 경로 확인, 기록 시작·종료, 리포트 확인, 다음 연습 선택까지 이어지도록 구성한다. 참여 제안과 백그라운드 기록은 별도 장면으로 준비해 핵심 흐름을 짧게 보여 줄 수 있도록 한다. 실제 SDK 연동 장면과 예시 데이터로 보여 주는 장면은 화면과 설명에서 구분한다.

촬영에 사용할 앱과 데이터를 고정하고, 같은 순서로 다시 실행해도 시연을 재현할 수 있도록 준비 조건을 적는다. 설치·실행 방법, 필요한 권한, 시연 순서, 구현된 기능과 남은 범위를 문서에 정리한다. 기존 문서 중 초기 구현 상태와 달라진 설명도 함께 갱신한다.

**11월 30일까지는 시연용 APK, 영상 초안, 실행 안내 문서를 모두 준비한다.** 영상을 만드는 과정에서 발견한 흐름상의 문제와 설명하기 어려운 화면은 이때 수정한다.

## 12월 1일~2일: 최종 점검과 수정 여유를 확보한다

이틀은 앞 단계에서 밀린 검증과 마지막 오류 수정을 위한 기간으로 확보한다. 새 기능은 추가하지 않고, 준비된 APK로 설치부터 시연 종료까지 전체 흐름을 다시 확인한다. 기존 앱 업데이트 후 기록이 유지되는지, 별도 초기 상태에서도 필수 설정과 권한 안내를 거쳐 정상적으로 진입하는지 점검한다.

빌드·린트·관련 테스트와 에뮬레이터 시연을 최종 확인하고, 영상에 사용한 버전과 전달할 APK가 일치하도록 맞춘다. 자료에서 설명한 기능이 실제 앱에서 동작하는지 대조하고, 확인하지 못한 기능은 완료 목록에서 제외한다.

**12월 2일까지 최종 APK와 시연 영상, 실행 안내 문서를 확정한다.** 마지막 날에 촬영이나 핵심 기능 구현이 남지 않도록 한다.

## 12월 3일: MVP 결과물을 정리한다

최종 APK와 시연 영상, 실행 안내, 검증 결과를 한곳에서 찾을 수 있도록 정리한다. 이 시점의 완료 기준은 다른 사람이 안내 문서에 따라 앱을 설치하고, 대표 사용 흐름을 재현하며, 실제 구현 범위를 확인할 수 있는 것이다.

12월 3일 이후에 진행할 작업은 남은 조건과 함께 별도로 기록한다. 실차 검증, 도로 적합성·실시간 교통을 활용한 추천, 차량·ADAS 데이터 기반 분석, 앱 미실행 상태의 참여 제안, 장기 성장 비교와 클라우드 기능은 이번 일정의 필수 완료 범위에 포함하지 않는다.

## 일정이 밀릴 때 지킬 우선순위

가장 먼저 지킬 것은 실제 목적지 확인부터 기록 저장·리포트 조회·다음 연습까지 이어지는 흐름과 기존 데이터의 보존이다. 기록 오류와 진행을 막는 문제를 해결한 다음 화면 완성도를 높인다. 자동 음성의 활성화와 추가 안내 유형은 검증 여건에 따라 후속으로 넘길 수 있다.

왕복 경로가 지원 환경의 제약으로 끝까지 검증되지 않으면, 검증된 편도 흐름으로 대표 시연을 확정하고 왕복 기능의 제한을 명시한다. 기능 범위를 조정하더라도 11월 30일에는 APK·영상 초안·문서가 갖춰지도록 하고, 12월 1~2일의 최종 점검 기간을 확보한다.
