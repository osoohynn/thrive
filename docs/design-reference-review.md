# Thrive UI 간소화와 공식 디자인 가이드 검토

> 이전 단계의 검토 기록이다. 이후 사용자 피드백으로 Figma 배경과 팔레트를 복원했다. 현재 기준은 [디자인 시스템](design-system.md)과 [Figma 기반 다듬기](design-refinement.md)다.

확인일: 2026-11-15. 사용자의 최신 요청은 오래된 인상의 장식과 감성 문구를 제거하고, 당근·토스의 디자인 시스템을 참고하는 것이다. 아래는 공개 공식 문서에서 확인한 원칙과 Thrive의 적용 판단이다. 문서 전체나 타사 자산을 복제하지 않았다.

## 확인한 공식 문서

| 문서 | 확인한 원칙 | Thrive 적용 |
| --- | --- | --- |
| [당근 SEED — Writing](https://seed-design.io/foundations/writing) | 하나의 목적에 집중하고 부가 설명을 줄인다. 버튼·메뉴·큰 제목은 마침표를 생략한다. | 감성 제목·권유 문장·반복 설명 삭제. 기능명과 값 중심으로 표시. |
| [SEED — Voice and Tone](https://seed-design.io/foundations/voice-and-tone) | 필수 정보를 명확하고 간결하게 전달한다. | 당근의 친근한 말투 전체를 도입하지 않고 사용자의 무문구 선호를 우선. |
| [SEED — Color](https://seed-design.io/foundations/color) | 색은 역할과 상태에 의미를 두고 충분한 대비를 확보한다. | 배경·표면·텍스트·선택·포커스를 공통 토큰으로 관리. |
| [SEED — Action Button](https://seed-design.io/components/action-button) | 강한 CTA는 한 화면에 하나, 보조 동작은 약한 강조로 구분한다. 브랜드색을 절제한다. | 홈의 주요 CTA 하나와 회색 보조 버튼. 알약형 버튼을 반경 16dp로 정리. |
| [SEED — Motion](https://seed-design.io/foundations/motion) | 미세 반응과 화면 단위 모션을 구분하며 미세 반응은 200ms 이하로 정의한다. | 누름·선택·토글은 120–180ms. 주행 중 장식 모션 없음. |
| [토스 TDS — ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/) | 좌측 요소·주요 내용·우측 동작을 구분하고 여백·터치 반응을 일관되게 제공한다. | 주행 기록을 카드 그리드에서 목록으로 변경. 기록과 동작을 정렬. |
| [TDS — Typography](https://tossmini-docs.toss.im/tds-mobile/foundation/typography/) | 역할에 따른 글자 위계와 큰 글자 설정 대응이 필요하다. | 제목 40sp, 본문 28/24sp를 유지하고 시스템 글자 배율·줄바꿈·세로 배치를 허용. |
| [TDS — Top](https://tossmini-docs.toss.im/tds-mobile/components/top/) | 제목·보조 정보의 역할과 접근성 위계를 구분한다. | 중복된 상단 분류 문구 제거. 기능 제목 하나와 필요한 값만 표시. |

## 현재 화면에서 제거한 요소

- 물결·점무늬 배경, 민트 그라데이션, 홈의 장식 경로 그림.
- “오늘의 길이, 내일은 익숙해지도록”, “조금씩 쌓이는, 나만의 길”, “지금의 나에게 맞춰서” 등의 감성 제목.
- 같은 기능을 다시 설명하는 문단, 선택 카드마다 반복되는 “운전 경험” 등의 라벨.
- 과도한 패널·내비게이션 테두리, 번호와 문구가 반복되는 단계 표시.
- 화면의 “저장됐어요” 문장. 실제 저장 성공 후 체크만 표시하고 접근성으로 완료를 알린다.

## 남기는 정보

기능명, 목적지·시간·거리, 버튼·선택값, 실제·시연 구분, 오류 해결 안내, 권한·기록 동의와 삭제 확인은 유지한다. 운전 경험·주행 느낌 선택값은 저장된 데이터와 연결되므로 기존 값을 유지한다.

## 적용 범위와 차량 화면 판단

공통 테마·헤더·버튼·선택 카드·칩·내비게이션·다이얼로그와 홈·목표·목적지·코스·출발 준비·리포트·기록·설정을 수정했다. 실제 SDK 연결과 저장 로직은 그대로 사용한다.

모바일 가이드의 작은 글자나 터치 크기를 차량 화면에 복사하지 않았다. 최소 터치 높이 64dp, 본문 24–28sp, 주행 수치 60sp를 유지한다. 색상·반경은 Thrive의 적용값이며 당근·토스의 공식 토큰값으로 표시하지 않는다. 브랜드 로고·일러스트·독점 폰트나 추가 UI 라이브러리를 도입하지 않았다.

## 렌더 리뷰와 검증 결과

Pleos 에뮬레이터 2560×1440, density 160에서 확인했다. 시스템 글자 배율 설정은 별도 값이 없는 기본 상태이며 변경하지 않았다. 넓은 앱 영역과 콘텐츠 폭 840/600dp를 확인했다. 작은 폭 검증은 Activity 콘텐츠 너비를 제한한 것으로, OS의 실제 분할 창 검증과 구분한다. Figma 플랫폼 원본은 이번에 다시 조회하지 않았고 기존 프로젝트의 Pleos 비교표를 참고했다.

| 우선순위 | 화면·위치 | Before | After | 근거 |
| --- | --- | --- | --- | --- |
| P2 · 수정 | 공통 배경·홈 | 물결·점무늬와 민트 그라데이션이 카드·텍스트와 겹침 | 단색 배경과 불투명 표면 | `ThriveBackdrop`, `DrivingHome`; 아래 홈 렌더 |
| P2 · 수정 | 모든 페이지 상단 | 분류·감성 제목·설명이 반복되어 상단을 크게 차지 | 기능 제목 하나, 필요한 값과 상태만 표시 | `PageTitle`의 공통 구조; 홈·목표·출발 준비·리포트 렌더 |

- `testDebugUnitTest`: 59개 통과, 실패·오류 0개. 정차·주행·키보드·시스템 모션 설정에 따른 모션 정책과 다이얼로그 콜백을 포함한다.
- 격리 패키지 `com.thrive.pleos.verification.figma`, 사용자 10의 `figma_ui`: 최종 빌드에서 43개 동작 통과, 27개 스크린샷. 코스/검색 빈 상태, 경로 선택, 출발, 리포트, 다음 연습, 동의창, 설정 저장, 삭제 취소를 확인했다.
- `motion_ui`: P단 수신, 실제 저장 후 완료 체크, 포인터 누름, 반복 토글, 모션 줄이기 저장, 다이얼로그 취소 후 탐색 통과.
- 일반 패키지 `com.thrive.pleos`의 `assembleDebug` 통과. APK: `app/build/outputs/apk/debug/app-debug.apk`. 일반 앱의 데이터는 초기화하지 않았다.
- `git diff --check` 통과.

기본 글자 배율에서 직접 확인한 화면에는 겹침이나 가로 잘림이 없었다. 작은 콘텐츠 폭에서는 세로 배열과 스크롤을 사용한다. 실차의 시청 거리, 큰 글자 배율, 실제 OS 분할 창, 키보드·차량 컨트롤의 포커스 이동과 스크린 리더 음성은 이번 렌더 검증에 포함하지 않았다. 시스템 모션 배율 0의 정책은 단위 테스트로 확인했으며 에뮬레이터의 전역 배율을 변경하지 않았다.

현재 우선 수정 항목은 반영을 마쳤다. 다음 디자인 수정 때는 공통 토큰과 컴포넌트부터 조정한다.
