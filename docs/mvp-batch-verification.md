# 2026-11-15 MVP 구현·검증

실행 환경: Pleos Android 14 에뮬레이터, NaviHelper 3.0.5, FusedLocation 1.1.3, Room 2.7.2. 기기 검사는 기본 앱과 데이터가 분리된 `com.thrive.pleos.verification`에서 실행한다. 실제 SDK 서비스 수신과 GPS 모의 입력을 구분한다.

## 추가한 동작

- 세션별 내비 사건: 경로 계산·재탐색·취소·목적지 변경·도착·TBT·오류를 앱 수신 시점과 함께 저장한다. APP 기록 시작/재개 표시는 SDK 사건과 구분한다.
- 리포트: 시점·출처와 최근 5/20건, 저장 한도 누락 수를 표시한다. 과거 기록에 사건을 만들어 넣지 않는다.
- 안내 후보: 실제 TBT 유형과 선택 목표를 연결하고 5초 만료, 30초 중복 억제, 음소거·경로 변경·종료 시 대기 문구 해제를 적용한다. 자동 TTS는 활성화하지 않는다. 내비·통화·차량 경고 우선순위는 별도 검증 사항이다.
- 복습: 저장된 재탐색/목적지 변경/취소/도착 사실을 사용자 느낌·선택 목표에 따른 다음 연습 이유에 덧붙인다. 수신한 길 안내로 운전자의 행동이나 실력을 판정하지 않는다.
- 저장: Room v3→v4 마이그레이션, 사건 키로 재시도 중복 방지, 메모리 대기 256건/기록당 2,000건 한도와 누락 수 표시. 종료 전 저장 실패 시 기록을 완료 처리하지 않고 다시 시도할 수 있다.

## 절전 환경의 경계

현 에뮬레이터의 `dumpsys deviceidle`은 `mLightEnabled=false`, `mDeepEnabled=false`, `mState=ACTIVE`였다. 이 조건을 강제로 바꾸지 않았다. 15분 검사는 화면 Activity가 없는 백그라운드 기록 검사이며 Android Doze나 제조사 전원 절전 통과를 주장하지 않는다. 해당 조건은 지원 기기·실차 검증 목록에 남긴다.

기본 앱은 현재 차량 사용자에 설치돼 있지 않아 신규 설치·실행했다. 설치 전 기본 앱 DB에는 접근할 수 없어 기본 앱의 이번 업데이트 전후 데이터 비교는 할 수 없었다. 위 9개 보존 결과는 별도 검증 패키지의 실제 v3→v4 비교다.

## 저장 및 수신의 한계

시간은 SDK 사건 발생 시각이 아니라 앱이 콜백을 받은 시각이다. 동일 TBT는 30초, 동일 일반 사건은 1.5초 동안 중복 억제한다. 저장되지 않은 구간의 실제 사건 수는 알 수 없다. 버퍼를 디스크에 쓰기 전 프로세스가 강제 종료되면 마지막 약 1초의 대기 사건을 잃을 수 있고, 앱 종료 중 신호는 재생되지 않는다. 저장 한도 누락 수가 모든 수신 누락을 뜻하지 않는다.

경유지 좌표가 없는 SDK 응답에서 요청값을 대신 끼워 넣거나 이름만으로 동일 장소를 판정하지 않는다. SDK의 유효한 POI ID와 제공자 정보가 일치하거나 실제 좌표가 일치해야 한다. 이 에뮬레이터에서 좌표만 있는 왕복의 전체 흐름은 지원 제한으로 남긴다.

정지한 에뮬레이터에서 위치 수신이 늘어도 실제 운전이나 도로 적합성 검증은 아니다. 실차·제조사 절전 정책, 장시간 전원 종료 후 자동 감지, ADAS 객체/차선 분석, 혼잡 기반 추천은 별도 조건이 필요하다.

## 재현

JDK 17과 프로젝트 SDK 환경에서:

```sh
./scripts/android.sh -PthriveVerification assembleDebug assembleDebugAndroidTest lintDebug testDebugUnitTest
python3 scripts/checks/verify-mvp.py --adb .tools/android-sdk/platform-tools/adb --serial emulator-5554 --user 10
```

진행 중인 검증 기록이 없어야 하며, 기본 내비 목적지와 필요한 권한이 준비돼 있어야 한다. 왕복 검사는 실제 내비 최근 목적지 중 POI ID가 있는 장소를 사용한다. 사건/왕복 검사는 테스트 동안 내비 경로를 바꾸며 finally에서 원래 목적지를 추천 옵션으로 다시 계산한다. 원래 옵션/경유지 전체를 복원하는 검사는 아니므로 개인의 진행 중인 여행에서 실행하지 않는다. 검증 앱에 테스트 기록이 추가된다. 기본 앱의 DB는 수정하지 않는다.

15분 연속 검사는 `--scenario mvp_stability`로 별도 실행한다. 수행 중 검증 앱을 업데이트하거나 종료하면 안 된다.
