# 운전 적응 UI 적용 및 검증

검증일: 2026-11-14

## 적용 범위

기존 `ThriveTheme`, `ThriveBackdrop`, `ThriveGlassPanel`, Pretendard와 공통 디자인 토큰을 사용해 HTML 디자인의 흐름을 네이티브 Compose로 구현했다. 테마 값, 시스템 바, 기존 휴식 목업 코드는 변경하지 않았다. `MainActivity`의 기본 진입과 Preview만 `DrivingApp`으로 연결했다.

화면: 홈, 지도 연동 체험, 연습 목표, 목적지 검색, 코스 선택, 출발 준비, 주행 시연, 주행 리포트, 주행 기록, 프로필.

## 빌드 검증

- 기존 의존성만 사용했다. 새 UI 라이브러리·웹뷰·SDK 의존성을 추가하지 않았다.
- 기존 프로젝트의 SDK와 의존성 캐시를 사용한 독립 작업 복사본에서 `assembleDebug lintDebug` 통과.
- Lint: 오류 0개. 기존 `OldTargetApi`, `DataExtractionRules` 경고 2개.
- 에뮬레이터의 기존 앱과 개발용 서명을 맞춰 `install -r`로 업데이트했다. 기존 앱을 삭제하지 않았다.

## 실행 검증

Pleos API 34 에뮬레이터, 전체 디스플레이 2560×1440에서 실제 Compose 렌더와 UI 계층을 확인했다. 차량 시스템 영역과 앱 콘텐츠를 구분해 확인했다.

- 홈과 네이비·시안 배경, 제목·본문·CTA 렌더 확인. 최초 확인에서 발견한 루트 텍스트 대비를 공통 Surface로 수정 후 재검증.
- 지도 연동 체험 → 참여 제안 → 수락 → 출발 준비 → 주행 시연 → 리포트 확인.
- 안내 끄기·켜기 상태와 문구 확인. 실제 음성 재생은 하지 않는다.
- 리포트 → 다음 연습 → 차선 변경 준비·45분 선택 → 코스 변경 → 출발 준비의 선택값 반영 확인.
- 시연 완료 기록과 이전 예시 기록 구분 확인.
- 프로필 경험 선택 후 홈 복귀 확인.
- 목적지 목록에서 뚝섬역 선택 후 코스·출발 준비에 목적지 반영 확인.
- 화면 전환 시 스크롤 초기화 확인.

## 미검증 및 제한

- 분할 창과 큰 글자 배율의 실제 렌더는 이번 실행 검증에 포함하지 않았다. 반응형 코드와 Compose Preview를 제공한다.
- 앱 종료 후 데이터 영구 저장, 실제 운전 평가, 내비게이션·Vehicle·ADAS·음성 SDK 연결은 구현하지 않았다.
- 지도 제안은 앱 내부 다이얼로그다. 다른 앱의 경로 감지나 시스템 헤드업 알림을 구현한 것이 아니다.
- 경로·시간·거리·주행 장면은 예시 데이터다. 실제 길 안내에 사용하지 않는다.

스크린샷은 기획 프로젝트의 `design/native-preview/`에 보관했다.

## 후속 가독성 수정

같은 날 공통 글자 크기와 표면 대비, 선택·포커스 표시를 개선했다. 위의 “테마 값은 변경하지 않았다”는 최초 화면 구현 단계의 기록이다. 이후 변경과 검증 범위는 [가독성 수정 기록](readability-review.md)에 정리했다.
