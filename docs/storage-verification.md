# 로컬 저장·세션 기능 1차 검증

검증일: 2026-11-14

## 구현 범위

- Preferences DataStore: 실제 운전 경험·관심 상황·음성 안내 설정.
- Room: 세션 ID, DEMO 출처, 선택 목표·모드·코스·목적지, 목표 시간, 시작·종료 시각, 실제 시연 경과 시간, 진행 상태, 부담 응답.
- 세션 상태: Recording → Completed, 프로세스 종료 후 Interrupted → 재개 또는 종료.
- 기록 조회·개별 삭제·완료 기록 전체 삭제. 진행 중 기록은 삭제 대상에서 제외.
- 새 시연을 시작할 때 활성 세션이 있으면 기존 세션을 유지하고 중단 복구를 안내한다.
- 실제 실행 시간과 코스의 목표 시간을 구분한다. 위치 미연동 상태에서 거리를 0이나 예시 거리로 기록하지 않는다.

## 검증 결과

- 기본 앱 ID와 분리 앱 ID 모두 `assembleDebug lintDebug testDebugUnitTest` 통과.
- 시간 계산 JUnit 테스트 3개 통과: 단조 시계 경과, 중단 중 시간 제외, 비정상 시각 방어.
- 실제 에뮬레이터에서 프로필 선택 후 앱 force-stop·재실행 시 유지 확인.
- 시연 시작·종료 후 SQLite 기록이 한 건 생성되고 DEMO 출처·실제 경과 시간·완료 상태가 저장됨을 확인.
- 앱 재실행 후 기록에서 리포트를 열고 부담 응답을 저장한 뒤 다시 읽어 확인.
- 기록 중 프로세스 종료 후 복구 안내 확인. 같은 세션 ID로 재개·종료되고 새 세션이 중복 생성되지 않음.
- 개별 삭제 후 앱 재실행·SQLite 조회로 삭제 확인. 다른 완료 기록은 보존됨.
- 현재 실제 차량 사용자 10의 앱 저장소를 기준으로 검사. 기본 사용자 0의 별도 저장소와 구분.
- SDK 서비스 연결·목적지 조회 콜백 수신은 `sdk-capabilities.md`에 별도 기록.

기본 앱이 다른 작업에서 재설치되는 현상을 관찰해 분리된 검증 앱을 사용했다. 검증용 기록과 설정은 기본 앱과 별도 저장소에 보관된다. 앱 데이터 초기화나 기존 사용자 기록 전체 삭제는 하지 않았다.

## 저장 정책과 한계

- 기록 중 약 5초마다 체크포인트를 저장한다. 강제 종료 시 마지막 체크포인트 이후 최대 약 5초의 경과 기록은 유실될 수 있다.
- 앱이 꺼져 있던 시간은 기록 시간에 포함하지 않는다.
- 위치 샘플·주행 사건 저장, 실시간 차량 기록, 내비 목적지 기반 실제 주행 세션은 다음 개발 범위다.
- 이 단계에서 생성한 기록은 운전 실력 평가나 실차 데이터가 아니다.
- 완료 기록 전체 삭제는 구현했으나 사용자 기록 보존을 위해 이번 UI 검증에서는 개별 삭제만 실행했다.
- 분할 화면·큰 글자·음성 설정 영구 저장의 별도 실행 검증은 이번 저장 검사에 포함하지 않았다. 기존 UI·테마는 유지했다.

## 주요 코드

- `driving/storage/DriverPreferences.kt`: 설정의 원자적 수정과 데이터 흐름.
- `driving/storage/DriveDatabase.kt`: 세션 저장, 활성 세션 유일성, 완료 조건부 갱신과 삭제.
- `driving/SessionTiming.kt`: 단조 시계 기준 시연 시간.
- `ui/driving/DrivingViewModel.kt`: 로드·저장·복구·타이머·화면 이벤트의 소유자.
- `app/schemas/`: Room 스키마를 버전 관리에 포함한다. 이후 변경 시 데이터를 보존하는 마이그레이션을 추가한다.
