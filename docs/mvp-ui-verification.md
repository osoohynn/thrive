# MVP 핵심 화면 렌더 점검

2026-11-15. 최신 Figma 적용 작업의 밝은 테마·에셋·메뉴·공통 다이얼로그를 보존하고 새 사건 리포트와 안내 후보만 연결했다. 기준은 현재 `docs/design-system.md`, 실제 Compose 토큰·컴포넌트다.

## 실행 범위

검증 패키지에서 MainActivity의 실제 `DrivingApp`을 렌더했다. Compose의 로컬 폭 1100dp/글자 배율 1.0과 480dp/1.3을 적용해 홈 → 목표 → 실제 경로 설정 → 저장 SDK 리포트 → 부담 응답 → 다음 연습 → 프로필 이동을 각각 통과했다. 에뮬레이터 전역 화면 밀도·글자 배율·테마는 바꾸지 않았다.

이는 실제 Compose에 제약을 준 검사이며 차량 시스템의 분할 창 리사이즈 자체를 검증한 것은 아니다. 캡처의 오른쪽 흰 영역은 앱에 준 로컬 폭 바깥이다. 시스템 상태바·Driving view·GNB는 앱 검토 범위와 구분한다.

## 발견·수정

| 우선순위 | 화면·위치 | Before | After | 근거 |
| --- | --- | --- | --- | --- |
| P1 | SDK 리포트 왼쪽 요약·사건 카드 | 새 두 번째 패널이 기존 요약 패널과 같은 Box 원점에 놓여 본문이 겹쳤다 | 같은 반응형 열 안에서 Column과 공통 섹션 간격으로 순서대로 배치했다 | `report-overlap-before.png`와 `1100dp-1.0font/04-event-report.png`, ReviewScreens.kt의 LiveReportSummary 호출부 |

겹침 수정 후 넓은 폭의 요약/복습 두 열과 작은 폭의 세로 배치에서 카드·긴 문구가 순서대로 읽힌다. 작은 폭에서는 아래 콘텐츠로 스크롤해 사건·느낌·다음 행동에 접근했다. 실제 경로 설정의 시간·편도/왕복·옵션 선택도 줄바꿈되며 계산 버튼에 접근했다. 선택 상태는 체크/테두리로 구분한다. 타이포를 임의 축소하거나 새 UI 의존성을 넣지 않았다.

첫 외부 `uiautomator dump`는 instrumentation과 접근성 연결이 충돌해 실패했다. 이 결과는 통과로 세지 않았다. 검사 내부 UiAutomation 연결로 재실행하여 패키지·화면별 앵커를 확인하고 PNG와 노드 경계를 저장했다. 단순 접근성 클릭 성공만으로 시각 검증을 통과시키지 않았으며, 실제 캡처에서 발견한 겹침을 수정했다.

## 근거와 한계

- 자동 결과: `PASS: 1100dp-1.0font ...`, `PASS: 480dp-1.3font ...`.
- 각 조건의 PNG 6장과 접근성 노드 JSON 6개를 보관했다. release 패키지의 `screenshots/`에서 확인할 수 있다.
- 핵심 화면 이동과 새 사건 카드·느낌·다음 연습을 점검했다. 현재 UI의 기존 빈 코스·검색/삭제 취소·시연 전체 흐름 검사 범위는 `figma-ui-verification.md`를 참고한다.
- 모든 OEM 창 크기, 실차 읽는 거리, 전체 키보드/로터리 포커스 순서, 공식 검수 전체 통과를 뜻하지 않는다. 문서의 토큰을 공식 필수 수치로 표현하지 않는다.
